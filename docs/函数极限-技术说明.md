## 二、取值与数值核验

判定标准：`sup|f(x) − 1| < ε` 时合格（x ∈ (1−δ, 1+δ)，x ≠ 1），f(x) = x²。

| 章 | ε | δ | sup│f−1│ | 结论 |
|---|---|---|---|---|
| ch04 | 0.8 | 0.6 | 1.5600 | 不合格 |
| ch05 | 0.8 | 0.34 | 0.7956 | 合格 |
| ch05 | 0.3 | 0.34 | 0.7956 | 不合格 |
| ch05 | 0.3 | 0.14 | 0.2996 | 合格 |
| ch05 | 0.15 | 0.14 | 0.2996 | 不合格 |
| ch05 | 0.15 | 0.07 | 0.1449 | 合格 |
| ch08 | 0.4 | 0.18 | 0.3225 | 合格 |
| ch09 | 0.70 | 0.30 | 0.6900 | 合格 |
| ch09 | 0.35 | 0.15 | 0.3225 | 合格 |
| ch09 | 0.16 | 0.07 | 0.1449 | 合格 |
| ch09 | 0.09 | 0.04 | 0.0816 | 合格 |
| ch09 | 0.05 | 0.022 | 0.0445 | 合格 |

理论最小 δ 为 `√(1+ε) − 1`：

| ε | 理论上限 | 表中 δ | 说明 |
|---|---|---|---|
| 0.8 | 0.3416 | 0.6 故意超界 / 0.34 刚好 | 演示用 |
| 0.3 | 0.1402 | 0.34 超界 / 0.14 不超 | 演示用 |
| 0.15 | 0.0724 | 0.14 超界 / 0.07 不超 | 演示用 |

ch05 的 0.34 / 0.14 / 0.07 三个值分别取上一档 ε 的理论上限
（0.8→0.34、0.3→0.14、0.15→0.07），因此 ε 再降一档时它必然失效，
这一联动就是该章的叙述主线。

## 三、第 8 章：δ 的求法

推导要避开三个错误。

**其一是循环论证。**
写成 `|x²−1| = |x−1|·|x+1| < δ·3 = ε ⇒ δ = ε/3` 不成立：
`|x+1| ≤ 3` 只在 x ∈ (0,2) 时成立，而 x ∈ (0,2) 本身是 δ ≤ 1 的结论。

**其二是假蕴含。**
`|x+1| < 3 ⟹ |x²−1| < 3δ` 推不出来。`|x+1|` 只是 `|x²−1|` 的一个因子，
它有界不足以断定乘积有界，必须同时使用 `|x−1| < δ`。

**其三是因果倒置。**
δ 不是由「令 3δ = ε」得到的。正确方向是：要 `|x²−1| < ε`，
只需 `3δ ≤ ε`，于是要求 `δ ≤ ε/3`；再加上 `δ ≤ 1` 的前提，
两者取较小者才得到 `min(1, ε/3)`。

现在的五步：

| 公式 | 说明 |
|---|---|
| \|x²−1\| = \|x−1\|·\|x+1\| | 平方差拆开，第一个因子正是 \|x−1\| |
| \|x−1\| < δ | 由 δ 邻域直接给出 |
| δ ≤ 1 ⟹ \|x+1\| < 3 | x 落在 (0,2) 内，故 x+1 在 (1,3) 内 |
| \|x²−1\| < δ·3 | 两个界相乘，得到不含 x 的上界 |
| δ = min(1, ε/3) | 要 3δ ≤ ε 就取 δ ≤ ε/3；又要 δ ≤ 1，取较小者 |

章末补一条代入验证：`|x²−1| < 3δ ≤ 3·(ε/3) = ε`。

排版上有两点要求：每排公式必须完整，不能出现 `< δ·3` 这种承接上文的碎片；
排距要真均等，做法是先把每排补齐到同一外框高度再等距排列，
否则含分式的 `min(1, ε/3)` 那排上下空隙会明显偏小。

## 四、镜头推近

实现方式是直接修改 `MovingCameraScene` 的 `camera.frame`，不再重画坐标系。

重画的做法有三个问题：刻度、标注、曲线都要重建，容易留下残影；
放大表现为瞬间的结构替换，看不出镜头在移动；倍率变化后所有文字与线宽
的世界尺寸都跟着改变，需要逐个补偿。

改用 camera.frame 后，世界坐标不变，图形自然放大；缩放是连续插值，
镜头呈现推进过程。需要在屏幕上保持固定大小的元素（字幕、状态牌、公式）
通过 `pin_to_screen` 钉住，它会记录屏幕归一化坐标并按倍率反向补偿尺寸。

实现中需要注意的三点：

- `pin_to_screen` 与 `fix_in_frame` 不能同时作用于同一物件，否则尺寸
  会被补偿两次，字幕越推越小。
- 字幕重新创建时的宽度上限要用当时的 `frame.width`，而不是
  `config.frame_width`，否则推近后字会显得过大。
- 放大后画面中上部被图形占满，字幕须临时移到底部，同时淡出 x₀ 标注，
  避免两者落在同一位置。

## 六、字幕与公式的写法

字幕正文在 `scenes/captiontext.md`，代码从该文件读取，改字无需改代码。
格式为一行 key、下一行正文：

```
[ch02_distance]
x 越靠近 1，纵坐标就越靠近 1——还是「距离」那件事
```

数学部分直接写 `x_0`、`ε`、`x^2`、`ε/3`、`|x - x_0|`，程序会自动
转换成下标、上标与分数。

`scenes/caption_keys.json` 是原句到 key 的映射表，作用是不必把现成的
字幕调用逐句改写。修改文案时不需要动它。

需要注意的技术限制：

- `Text` 不支持 Unicode 上下标，会渲染成方框，因此字幕统一走 `rich_text`。
- `MathTex` 中不能出现中文，`\text{令}` 会直接报错，中英混排须拆成
  `Text` 与 `MathTex` 再拼接。
- 破折号 `——`（U+2014）落在 CJK 判定区段之外，需在 `CJK_RE` 中补齐，
  否则会被送进 LaTeX 渲染成竖线。

python -m manim -ql scenes/function_limit.py FunctionLimit    # 480p15 预览
